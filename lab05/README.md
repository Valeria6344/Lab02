### Задание 4 **(2)**

*Рассмотрим следующий пример в IDLE Python*
```
>>> x = 99.99
>>> int(x/10+0.001)
9
```
*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*

Причина ошибки связана с особенностями представления вещественных чисел в компьютере. 
Некоторые десятичные дроби нельзя точно представить в двоичном формате, поэтому при вычислениях возникает небольшая погрешность. 
Вместо точного значения 10 может получиться число, немного меньшее десяти, например 9.999999999999998.

Функция int() отбрасывает дробную часть числа, а не округляет его. Поэтому число, немного меньшее 10, преобразуется в 9.

Для исправления программы можно использовать функцию round(), которая округляет результат до ближайшего целого числа:

x = 99.99
print(round(x / 10 + 0.001))

Результат выполнения:
10
Также необходимо учитывать, что Python различает заглавные и строчные буквы: переменные X и x считаются разными переменными. Поэтому имя переменной в объявлении и при использовании должно совпадать.


### Задание 5. **(2)**

*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,
как величина* $y$ *повлияла на ответ?*
```
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y*=10
```
*В отчете требуется привести вычисления для оценки погрешности*

Математически выражение ((x+y)-y) = (x), поэтому ожидаемый результат каждой итерации — (1/3).
Однако число (1/3=0.333333\ldots) является бесконечной периодической дробью и хранится в компьютере приближённо. 
Переменная y после каждой итерации увеличивается в 10 раз. Когда y становится намного больше x, при вычислении x + y небольшая дробная часть может потеряться из-за ограниченной точности типа float.
После вычитания y потерянная часть не восстанавливается, поэтому результат может отличаться от (1/3), а при достаточно большом y может стать равным 0.0.
Абсолютная погрешность вычисляется по формуле:

[\Delta=\left|\frac13-r\right|,]

где (r) — результат программы. Если результат равен 0.0, абсолютная погрешность составляет примерно (0.333333).

Таким образом, пример демонстрирует погрешности представления вещественных чисел и потерю значимости при арифметических операциях с числами, сильно различающимися по величине.

### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?
```
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```

Функция pow(2, n) вычисляет степень двойки (2^n). 
Тип double имеет ограниченный диапазон представимых чисел. 
Его максимальное конечное значение приблизительно равно (1.7976931348623157 \times 10^{308}).
Степень (2^{1023}) ещё представима в формате double, но (2^{1024}) превышает максимальное конечное значение. 
Поэтому при использовании стандартного формата IEEE 754 минимальное значение n, при котором появляется inf, равно 1024.
inf обозначает бесконечность и появляется при выходе результата за пределы диапазона представимых конечных чисел.
Тип long double может иметь больший диапазон. 
Например, в расширенном 80-битном формате первое переполнение при вычислении степеней двойки происходит при (n=16384). Однако конкретный результат зависит от платформы и реализации типа.
Чтобы вычисление действительно выполнялось с использованием long double, следует передать функции pow аргумент этого типа, например pow(2.0L, n). 
Если просто изменить тип переменной, оставив вычисление в double, расширенный диапазон может не использоваться.

### Задание 7 **(2)**

*Допишите что-либо вместо многоточия программе на С++, чтобы программа при запуске выдавала ответ* **yes**.
```
double s = ...;
if (s != s)
  std::cout << "yes";
```

Необходимо присвоить переменной s специальное значение NaN (Not a Number — «не число»). По правилам сравнения вещественных чисел NaN не равен даже самому себе, поэтому условие s != s будет истинным.

Пример программы:

```
#include <iostream>
#include <limits>
using namespace std;
int main() {
    double s = numeric_limits<double>::quiet_NaN();
    if (s != s)
        cout<<"yes";
    return 0;
}
```
Результат выполнения: yes

Таким образом, программа выводит yes, потому что значение NaN не равно самому себе.

### Задание 8 **(2)**

*Какое минимальное натуральное число при преобразовании в тип* **double** *записывается с погрешностью? Объясните
ответ. Почему следующее за ним число уже выводится без погрешности?*

В стандартном формате IEEE 754 тип double имеет 53 бита точности для значащих цифр: 52 бита мантиссы и одну неявную ведущую единицу.
Поэтому все целые числа от (0) до (2^{53}) включительно представляются точно. Число

[2^{53}+1=9007199254740993]

является наименьшим натуральным числом, которое нельзя точно представить в double. При сохранении оно округляется до соседнего представимого числа.

Следующее число, [2^{53}+2=9007199254740994,] представляется точно, поскольку на этом участке диапазона шаг между соседними представимыми числами равен двум.

Таким образом, при больших значениях double уже не способен точно хранить все целые числа подряд: расстояние между соседними представимыми значениями постепенно увеличивается.

###  Задание 9 **(2)**
*Напишите программу для решения следующей задачи.*

*Даны четыре рациональных числа. (Рациональное число - это число вида*
$\frac{p}{q}$, *где* $p$ *и* $q$ - *целые числа.) Напишите программу, которая сравнит сумму
двух первых чисел с суммой двух последних чисел. Программа должна выводить* $1$, $0$ *или* $-1$
*в зависимости от результатов сравнения. Решение можно проверить в проверяющей системе*
[http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102](http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102), *задача 03*.

Для сравнения рациональных чисел можно использовать целочисленные вычисления, чтобы избежать погрешностей типа double.

```
#include <iostream>
using namespace std;
int main() {
    long long a, b, c, d, e, f, g, h;
    cin >> a >> b >> c >> d >> e >> f >> g >> h;
    long long first = a * d + c * b;
    long long first_den = b * d;
    long long second = e * h + g * f;
    long long second_den = f * h;
    long long left = first * second_den;
    long long right = second * first_den;
    if (left > right)
        cout << 1;
    else if (left < right)
        cout << -1;
    else
        cout << 0;
    return 0;
}
```
1. Программа считывает числители и знаменатели четырёх рациональных чисел.
2. Вычисляет числитель и знаменатель первой суммы:
    [\frac{a}{b}+\frac{c}{d}=\frac{ad+cb}{bd}.]
3. Аналогично вычисляет вторую сумму:
    [\frac{e}{f}+\frac{g}{h}=\frac{eh+gf}{fh}.]
4. Сравнивает дроби перекрёстным умножением, не выполняя деление.
5. Выводит 1, 0 или -1 в зависимости от результата сравнения.

Использование целочисленной арифметики позволяет сравнивать рациональные числа без погрешностей, связанных с представлением вещественных чисел. При этом необходимо учитывать, что для очень больших входных значений промежуточные произведения могут переполнить тип long long.
